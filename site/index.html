Building blocks for menu bar and tray apps

The parts every little desktop app needs and nobody wants to write twice: a reminder scheduler, permission-free system signals, app-shell plumbing and, for a desk companion, a character that talks and knows when to be quiet. Swift for macOS, .NET for Windows.

import LachingCore
import LachingSystem

let scheduler = ReminderScheduler(
    config: SchedulerConfig(
        interval: 45 * 60,
        quietHours: [12]
    ),
    clock: SystemClock(),
    idle: SystemIdleTimeProvider(),

// Call every 20 s or so.

}

    // Mic or camera in use: hold the reminder.

    ShowBreak();

Never prompts

Every system signal reads device and window state. Nothing opens the camera or microphone, nothing asks for Accessibility, nothing needs an entitlement you would have to explain.

Never phones home

No network code anywhere in the package: no analytics, no update checks, no telemetry. The Swift package has no dependencies at all.

One behavior, two platforms

The Swift code is the reference. JSON vectors generated from it are replayed by the C# port, so the two cannot quietly drift.

What's inside

Seven Swift products and six NuGet packages. Take the pure logic alone, the whole shell, or the companion on top.

LachingCore
Laching.Core

Scheduling and pure logic

An interval timer with active hours and weekdays, quiet hours, an idle reset ("you were away, the timer restarts"), a hold while the user is busy with a grace period after, snooze, "after my next call" and pause. Runs on an injected clock, so it builds and tests anywhere Swift or .NET runs.

ReminderScheduler SchedulerConfig Clock IdleTimeProvider BusyStateProvider SplitMix64

LachingCompanion
Laching.Companion

A desk companion's core

A phrase bank and picker (lines, jokes told in beats, tunes; scoped by skin, flavor and language), chatter cadence, quiet rules and mood, write-through settings your app extends, a coordinator that replays a whole day from a seed, desktop presence, skins, and a rig that animates vector or painted-layer character art. Your app brings the lines, skins and palette. Pure, so it builds and tests anywhere.

PhraseBank PhrasePicker QuietRules CompanionSettings CompanionCoordinator SkinCatalog RiggedCharacter

Laching.Windows

System signals

Idle time since the last input. Whether another app is using the camera or microphone. Full-screen apps, power source and battery level, output muted and route, screen locked, light and dark appearance. Each exposes a current value and a change callback.

SystemIdleTimeProvider SystemBusyStateProvider SystemPowerSource SystemAudioOutput ScreenLockWatcher AppearanceWatcher

LachingShell
Laching.Windows

App shell

A window manager that shows the Dock icon only while a window is open, a login item toggle and "was I launched at login?", notifications with categories and actions, a floating desktop window for a pet or a sticky note, a native tray icon and menu, single-instance startup, and drawing helpers for SVG paths, keyframes and a hand-drawn wobble. On the Mac also a status item with a popover and an animated glyph, and speech: the system voice or recorded clips, jokes told in beats, chimes. On Windows those come with the companion shell, below.

LachingCompanionUI

The companion on screen

The character view (vector and image parts), the character and its speech bubble on the desktop, the menu bar or tray glyph, delivery through bubble, voice, chime and notification, the system signals gathered into one snapshot, a palette your app sets, and a screenshot mode. Fakes, fixtures and vectors for your tests

A fake for every protocol, a fixture phrase bank and skins, and the conformance generators and replays: your app's Swift tests write its own companion vectors from the standard case lists plus its own, its .NET tests replay them.

MockClock MockIdle MockBusy MockStoreBackend ConformanceSuite CompanionVectors CompanionReplay

The package ships no strings, product ids or window lists. Your app passes them in, already localized.

Building a companion? tools/ has the scripts and agent skills that go with it: localization, phrase sync, recorded voices, character art, sounds, screenshots, the store listing and checks, and @laching/landing on npm for the landing page. You vendor them as a submodule and run them on your machine; none of them ship in your app.

Knows you're on a call. Never asks.

A break reminder that pops up mid-meeting gets uninstalled. Laching holds a due reminder while another app is using the camera or the microphone, and it finds out without ever opening a device, so there is no permission dialog and nothing for a reviewer to question.

If a device can't be read, it reads as not busy. Your app never blocks on a signal.

macOS Microphone
CoreAudio's list of processes using an input device.
macOS Camera
AVFoundation device state by default, CoreMediaIO for a sandboxed app without the camera entitlement, or off. The microphone alone catches nearly every call.
Windows Camera and microphone
The capability access consent store: Windows records when each app starts and stops using a device, and a start without a stop means it is in use now. No manifest capability needed.
Both Full screen
A full-screen app, game or presentation holds the reminder too.

Proven the same on both sides

Each scheduler and companion behavior is written down once, as JSON generated from the Swift code. XCTest checks the Swift side reproduces it, xUnit replays every vector against the C# port. A change on one side fails the other side's build.

Install

One tag per release: Swift takes the tag, and the NuGet packages get a new version only when they changed, so theirs can trail it. Laching is 0.x until the second app has settled the API, so pin an exact version: minor releases may change public types.

Swift Package Manager

macOS 14+, Swift 6 language mode, no dependencies

// Package.swift
.package(url: "https://github.com/vmihalachi/laching", exact: "0.19.17")

// then, per target
.product(name: "LachingCore", package: "laching")

Or in Xcode: File › Add Package Dependencies, paste the repository URL, pick Exact Version.

Used by

Laching was extracted from mybackhurts, which ships it, and sunnysays, in development, whose character skeleton became the companion layer. Mister Pagliacci is the second companion built on that layer.

mybackhurts

A break reminder for the menu bar

The first app to use Laching. Its scheduler, system signals and shell plumbing were generalized into the package, and its 37 scheduler vectors are the first ones in the conformance suite.

sunnysays

A desk companion

A character that says lines on a cadence, knows when to be quiet, stands on the desktop and speaks with recorded voices. Everything under the character was generalized into the companion layer and its tools. In development.

Mister Pagliacci

A clown who tells jokes

The second companion app, and the first built on the companion layer from the start: his jokes, skins and recorded voice are his own, the mechanism is Laching's. In design.
