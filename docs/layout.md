# Layout

Where things live, folder by folder (moved from `AGENTS.md`). Every Swift file has a C# twin, at the same relative
path unless its row below says otherwise, so `grep -rn` on a type name finds both sides; the Kotlin side (`kotlin/`)
mirrors `LachingCore` and the Android plumbing only. `web/` has no Swift twin: it is .NET only and shares nothing with
the rest.

| Path | Contents |
|---|---|
| `Package.swift`, `Sources/Laching{Core,System,Shell,Companion,CompanionUI,Store,Testing}/` | The Swift products (one folder each). `LachingCore` imports Foundation only (and CoreGraphics in `Drawing/`, on Apple platforms): `Scheduling/`, `Random/`, `Localization/`, `Settings/`, `Drawing/` (`LachingShell` keeps typealiases for its types). `LachingCompanion` imports Foundation and Observation only: `Phrases/`, `Cadence/`, `Rules/`, `Settings/`, `Coordination/`, `Desktop/`, `Figures/`, `Skins/`; it and `LachingTesting` (`Fixtures/`, and `Conformance/`: the suite, the generators, the standard case lists and `CompanionVectors` apps reuse) build on Linux. `LachingShell` has `Speech/` (speaker, sequencer, voice library, chime) and the status item; `LachingCompanionUI` (macOS) puts the companion on screen: signals, glyph, character view, desktop presence, delivery, notifier (`ConfiguredCompanionNotifier` adapts injected titles and action ids directly to the shell), `Theme/` (palette, spacing, speech bubble, status pill, the window chrome), `Shell/` (the app model apps subclass, its delegate, the menus, the copy structs), `Settings/` (rows and editors), `Support/` (the Support window) and `Screenshots/` (the screenshot script). A view or model here takes its words from the app: a `Text` per label or a copy struct, never a default. |
| `Tests/<Product>Tests/` | XCTest, one test target per product. `LachingCoreTests/Conformance/` generates and replays `conformance/scheduler`, `LachingCompanionTests/Conformance/` `conformance/companion`. `LachingTestingTests` covers the test kit itself: the mocks, `MockStoreBackend`, `JSONValue`, `BankAudit` and the conformance suite. |
| `Tests/Fixtures/characters/` | Art sources for the fixture skins (`fixture-vector`: SVGs; `fixture-raster`: layer PNGs), compiled by `scripts/fixture-art.sh` into `LachingTesting/Fixtures/Fixture*Art.swift` and `conformance/companion/characters/`. |
| `conformance/` | Generated vectors (`scheduler/`, `companion/`). Never hand-edit; `scripts/conformance.sh`. Formats in `conformance/README.md`. |
| `dotnet/Laching.Core/` | Pure C# mirror of `LachingCore`, file for file, plus `Store/` (mirrors `LachingStore`; its `MockStoreBackend` mirrors `LachingTesting`'s, shipped here because apps use it in preview modes), and `Localization/StringTable.cs` (C# only: the `.resw` lookup, plurals and fallback that `Laching.Windows`' `Loc` and `Laching.Testing`'s `ReswStrings` share). `IsAotCompatible`. |
| `dotnet/Laching.Companion/` | Pure C# mirror of `LachingCompanion`, folder for folder, plus the loaders `Phrases/PhraseBankJson.cs` and `Figures/CharacterArtJson.cs`. `IsAotCompatible`. |
| `dotnet/Laching.Companion.Shell/` | The platform-free half of a companion app's shell (0.8, `plans/0.8/`): the C# twin of `LachingCompanionUI`'s and `LachingShell`'s logic, mirrored **by role, not file for file** (*The map* in `plans/0.8/README.md`), written against small interfaces (`ISpeaking`, `IChimePlaying`, `ITimers`, the signal sources) so its tests run on any OS. `Speech/` (sequencer, voice library), `Performance/` (`DeliveryPerformer`, phrase localization, pending ids), `Signals/` (`SignalHub` and its source interfaces), `Desktop/` (layout and placement in y-down screen coordinates), `App/` (`CompanionAppModel<TWindow, TSettings>` over an `ICompanionHost<TWindow>`, started as an `ICompanionLaunching`, the copy records, `CompanionMenus` building `MenuItem` data), `Screenshots/` (`SampleEnvironment`). `IsAotCompatible`. |
| `dotnet/Laching.Testing/` | Mirrors `LachingTesting` for .NET apps' test projects (no xunit): mocks, `Conformance/` (root, support, `Companion/*Replay.cs` bodies and `CompanionReplay`, one call per file kind), `Fixtures/` loading `conformance/companion/` (and `Fixture`, the set loaded once; `FixtureCopy` with `FixtureWindow`, the fixture model's placeholder words), and `Shell/` (`ManualTimers`, `FakeSpeaker`, `FakeChime`, `FakeNotifier`, the signal fakes `FakeAudio`, `FakePower`, `FakeAppearance`, `FakeScreenLock`, `FakeHost<TWindow>` with its status item, windows, desktop window) for the shell's tests. |
| `dotnet/Laching.Windows/` | Win32 / Windows App SDK services (`net10.0-windows10.0.22000.0`, so Windows 11 and later; no XAML). Restores on Linux and macOS with `EnableWindowsTargeting`, but its Windows App SDK PRI step needs Windows: build it through `dotnet.yml`'s windows job. `System/` and `Shell/` (with `Shell/Localization/`, `WindowManager<TId, TWindow>` for window ownership and activation, `ThemeBinding` for loaded controls, and `XamlResources` for Native AOT safe resource lookup). Window creation, placement and maximization remain app policy. |
| `dotnet/Laching.Windows.Companion/` | The Windows half of the companion shell (0.8, `plans/0.8/`), over `Laching.Companion.Shell` and `Laching.Windows` (`net10.0-windows10.0.22000.0`, Windows 11 like it; WinUI 3, code only: no XAML, so no resources an app must merge). `Speech/` (`Speaker`: recorded clips and the speech synthesizer through `MediaPlayer`, kept out of the system media controls; `ChimePlayer`), `Shell/` (`CompanionApp`, the app's `Application` and its `App.xaml` root: one copy running, a quiet launch at sign-in, reopening, and `Start` as the whole of `Main`; `WindowsCompanionHost<TWindow>` with the app's `CompanionViews`, `WindowManager<TWindow>` over `WindowSpec`s, `TrayStatusItem` with its glyph and panel, `GlyphRenderer`, `DispatcherTimers`, `CompanionNotifier`, `MenuConversion`, `ReduceMotion`), `Signals/` (the system's mute, lock, power and appearance as the shell's signal sources), `Views/` (`CharacterCanvas` with its pure `CharacterMotion`, `CharacterScene` and `CharacterImages`, posed through composition transforms on one `FrameClock`; `CompanionPalette` and `CompanionLook`, the look every control paints from; `SpeechBubble`, `StatusPill`, `ActionBar`, `PanelRow`, `Pointer`, `Space` and `WindowInset`; `Announcer`, the polite Narrator notifications they and the Settings rows raise), `Desktop/` (`DesktopCompanion` over `DesktopWindow`, a layered no-activate tool window that passes clicks through where the character isn't drawn), `Settings/` (the rows and editors, each over a copy record), `Support/` (`SupportWindow`), `Screenshots/` (`ScreenshotCapture`, `ScreenshotScript`). Builds and tests on Windows only, like `Laching.Windows`. |
| `dotnet/Laching.Core.Tests/`, `dotnet/Laching.Companion.Tests/` | xUnit; `Conformance/` replays every vector (`scheduler/`, `companion/`). |
| `dotnet/Laching.Testing.Tests/` | xUnit, any OS: the test kit itself, the mocks, `MockStoreBackend`, `ManualTimers`, the conformance helpers (root, support, the vectors' JSON) and the fixture loaders. |
| `dotnet/Laching.Companion.Shell.Tests/` | xUnit, any OS: the Swift shell tests ported case for case (`SpeechSequencerTests`, `VoiceLibraryTests`, `DeliveryPerformerTests`, `DesktopLayoutTests`, `FloatingPlacementTests`, `CompanionAppModelTests` with the launch and host cases Swift can't run), over the Swift tests' own `Resources/Voice` and sunflower. |
| `dotnet/Laching.Windows.Tests/` | xUnit for `Laching.Windows`; runs only in `dotnet.yml`'s windows job. |
| `dotnet/Laching.Windows.Companion.Tests/` | xUnit for `Laching.Windows.Companion`, an unpackaged host; runs only in `dotnet.yml`'s windows job. Speech tests play generated WAVs at no volume: real playback where there is an audio device, the failure path where there isn't (a CI runner), and the line ends either way. The shell tests cover what runs without a WinUI app (the glyph's drawing and timing, the menu conversion, the placement next to the tray, the signal adapters, which launches show Home); the views' tests cover their pure parts (the character's scene and hit test against the pose vectors, the bubble's outline, the desktop bubble's place, the Settings rows' and Support's logic). Windows, the panel, the desktop character, notifications and the app's launch are checked by running the fixture app, and its screenshot run draws every window. |
| `dotnet/Fixture.App/` | The fixture app (Windows only, unpackaged, never packed): `Laching.Windows.Companion` running `CompanionAppModel` over the fixture bank, the fixture vector character in the tray, XAML windows (Home, Settings, onboarding) and panel built from the package's controls (the character canvas, bubble, pill, Settings rows, `SupportWindow` over a mock store), the raster fixture from its PNGs, Georgia as the bubble's display face, the desktop character, speech through the system voice, tones written at launch for the sounds, settings in memory (but the language picked in Settings, kept in `%LOCALAPPDATA%\Laching Fixture\settings.json` as an unpackaged app keeps it). Home has the hand checks' controls: a long line to start a call during, a clock that skips to the next line, the desktop character on and off, the panel. Run it with `dotnet run --project dotnet/Fixture.App` (`--first-run` for onboarding); the checks still to do by hand are the issues labeled `hand-check`. `scripts/fixture-screenshots.ps1` renders its windows in light and dark. |
| `kotlin/` | The Kotlin side, a standalone Gradle build (Gradle 9 wrapper, AGP 9.4, Kotlin 2.4; `gradle.properties` carries `lachingVersion`, `gradle/libs.versions.toml` the versions) that an Android app includes with `includeBuild` and dependency substitution (`laching:core`, `laching:android`, `laching:testing`; `tools/README.md` step 7): nothing is published. Build and test with `JAVA_HOME` (17) and `ANDROID_HOME` set inside the command: `./gradlew :core:test :testing:test :android:assembleDebug`; `ktlint` formats it. No Companion in Kotlin until a companion app goes to Android. |
| `kotlin/core/` | `laching.core`, pure JVM (kotlinx-serialization-json only): `Laching.VERSION` (generated from `kotlin/gradle.properties` by `core/build.gradle.kts`), `scheduling/` (`ReminderScheduler`, `SchedulerConfig`, `SchedulerState`, `Clock`, the idle and busy providers; ported file by file from `dotnet/Laching.Core/Scheduling` and checked against `Sources/LachingCore/Scheduling`), `random/` (`SplitMix64`), `localization/` (`LocalizedKey`, `PluralRules`, `ResourceNames`), `settings/` (`SettingsStore`), `store/` (`PurchaseStore`, `StoreBackend`, `ProductCatalog`, `MockStoreBackend`, as `Laching.Core/Store`), `drawing/` (`SvgPath`, `Wobble`, `Keyframes`, `Geometry`: the point math of `Sources/LachingCore/Drawing`, returning point lists the app draws). `src/test/`: `SchedulerConformanceTests` replays every `conformance/scheduler` vector; the SplitMix64, plural, settings, store and drawing tests ported from the Swift and C# suites. |
| `kotlin/android/` | `laching.android`, an Android library (minSdk 26, compileSdk 36): `LaunchContext` (the screenshot run's intent extras: `LACHING_SCREENSHOT_MODE`, `LACHING_SCREENS`, `LACHING_LANG`, `LACHING_REGION`), `ScreenshotRun` (draws each screen in light and dark into `files/screens/`, the app's sheets and dialogs over it from Android 14, writes `problems.txt` and `done`, then finishes the task), `PlayBillingBackend` (a `StoreBackend` over Play Billing), `SharedPreferencesSettingsStore`, `ReminderAlarms`, `ReminderNotifications`, `ReduceMotion`. |
| `kotlin/testing/` | `laching.testing` (JVM): `Mocks.kt` (`MockClock`, `MockIdle`, `MockBusy`, `ScriptedRandom`), `MockStoreBackend`, `ConformanceRoot` (finds `conformance/` walking up from the working directory, as `Laching.Testing` does) and `ConformanceSupport`, for an app's tests. |
| `tools/` | Tools for companion apps, which vendor this repo as a `laching/` submodule (`tools/README.md`): every one reads the app's `companion.json` (`companion.py`, `companion.schema.json`). `l10n.py`, `phrases.py`, `voice.py`, `character.py`, `synth.py`, `fonts.py`, the shell scripts (`verify.sh`, `setup-linux.sh`, `screenshots.sh`…), `verify-lib.sh` and `verify-lock.py` (bounded checks, cancellation, shared build locks and changed-path discovery; apps register their own checks), `ci-macos.py` (the reusable macOS workflow's configured checks), `hooks/hook.py`, `windows/` (the WinUI app kit: `companion.targets` every app's project imports, the screenshot runner and its layout check, the Store release `store-release.ps1` and its package smoke test, `check-winui.py`, `assets.py`), `store/` (the listing's checks, App Store Connect push, Partner Center import and submission push), `conform.py` (`companion.py conform`: the apps use these tools, not copies), `landing/` (`@laching/landing`, published to npm) and `skills/` (the apps symlink them). Shared by every app, so no file names one. Tests in `tools/tests/` over `fixture-app/`. |
| `web/` | The web packages (formerly Webling), a standalone .NET 10 build apart from `dotnet/`'s Native AOT desktop one: `Laching.Web.sln`, its own `Directory.Build.props` (`LachingWebVersion`, the six packages' one version), `Directory.Packages.props` (central package versions), `Directory.Build.targets`, `global.json` and `.editorconfig`. Used by Adjudeca, not by the companion apps. `web/README.md` is packed into each package. |
| `web/src/` | `Laching.Web.Jobs` (the PostgreSQL job table: `JobModelBuilderExtensions.ApplyLachingWebJobs`, the dispatcher, the `Laching.Web.Jobs` activity source), `Laching.Web.AspNetCore` (the Cloudflare origin check, security headers with the CSP nonce, `[PublicPage]` caching), `Laching.Web.Cloudflare` (Turnstile behind `IHumanCheck`, cache purges), `Laching.Web.Aspire` (Cloudflare-only Container Apps ingress with the bundled `cloudflare-ips-v4.txt`, `RunJobBeforeApps`), `Laching.Web.Tailwind` (build only: `build/Laching.Web.Tailwind.targets` pins the standalone CLI's version and SHA-256s, cached in `~/.laching/`), `Laching.Web.Images` (signatures, `UploadStream`, `ImageEncoder`). |
| `web/tests/` | `Laching.Web.<Name>.Tests` (xUnit; the Jobs tests run against PostgreSQL from `LACHING_WEB_TEST_POSTGRES`, default localhost:5432, each in its own `laching_web_` database) and `Laching.Web.Tailwind.Sample`, never in the solution: `web/scripts/tailwind-sample.sh` packs `Laching.Web.Tailwind` and builds the sample against the package. |
| `scripts/` | `verify.sh` (checks for what changed), `release.sh` (the release's `plan`, whether `nuget`, `web` and the `landing` ship, the `bump`; run by `release.yml`), `conformance.sh`, `fixture-art.sh` (compiles the fixture skins; `--check`), `agent-stop-check.sh` (`verify.sh --fast` as an agent Stop hook), `fixture-screenshots.ps1` (Windows: the fixture app's screenshot run). |
| `.agents/skills/` | Agent skills (see *Skills* in `AGENTS.md`); `.claude/skills`, `.junie/skills` and `.github/skills` are symlinks to it. `.codex/` holds Codex config and rules. |
| `plans/` | The design and sequence briefs of 0.5, 0.7 and 0.8, all released, kept as the record of why things are as they are (nothing new goes here: see *Planned work* in `AGENTS.md`): `plans/0.5/README.md` is the companion-layer design, `1-…`–`6-…` the sessions that built it; `plans/0.7/README.md` the companion shell (0.7.0: what the apps still repeat on top of 0.6 moves here), `1-…`–`6-…` its sessions; `plans/0.8/README.md` the Windows companion shell (0.8.0: `Laching.Companion.Shell` and `Laching.Windows.Companion`), `1-…`–`5-…` its sessions. |
| `.github/workflows/` | `swift.yml` (macos-26), `dotnet.yml` (ubuntu + windows), `kotlin.yml` (ubuntu: ktlint, the `:core` and `:testing` tests, the `:android` build), `release.yml` (on demand: plan, bump and tag, the changed NuGet packages and web packages, the landing, the GitHub release), `tools.yml` (the Python tools' tests), `web.yml` (`web/`: format, build and tests with a postgres service, the Tailwind sample on three OSes, and every Monday the Cloudflare ranges check), `regenerate-vectors.yml` (manual, on a branch: it refuses the default branch), `copilot-setup-steps.yml` (Copilot's cloud agent); `macos-app.yml`, `windows-release.yml` and `windows-app.yml` run in the apps, not here: reusable workflows (`workflow_call`) that an app's own short workflows call for Mac checks, the Store release and the WinUI build check (`tools/README.md`, *Windows apps*). |
